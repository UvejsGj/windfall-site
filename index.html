Windfall.

An apple the wind has dropped from the tree.

AirDrop for Windows and Linux, rebuilt from the bytes up.

Windfall is a from-scratch implementation of Apple's AirDrop protocol, worked out by capturing and measuring it. Nothing is wrapped and nothing is taken on faith: every layer is tested against software we did not write. Real iPhones have AirDropped photos to it, and they arrived byte for byte.

The one thing to understand first.

AirDrop finds its peers over AWDL, a second Wi-Fi link layer that shares the radio with the normal connection in time slots, on a schedule kept by every Apple device in range. Windows gives an application no way to drive a Wi-Fi card like that, and an iPhone looks for AirDrop nowhere else.

The beacon that starts every transfer shows why there is no way around it. It is 18 bytes long.

0p11p22p33p4 400500600700 803 9a110a211f112f213b114b215e116e2 1700
  • 0 to 3, a prefix. It carries data and is not yet explained.
  • 4 to 7 and 17, zeros. The closing zero has held since iOS 12.
  • 8, a version. Older research found 01. This phone sends 03.
  • 9 to 16, four short values. Two are the first two bytes of a SHA-256 of the owner's phone number and email.

No field names a channel, an address or a transport. The beacon cannot send a peer anywhere else. It can only mean: wake AWDL.

Why it is slow

The speed is the radio, and that is measured. The card under test can only listen in plain monitor mode, so it never acknowledges the frames the phone sends. The phone takes each frame as lost and sends it again until it reaches its retry limit.

sentagainagainagainagainagainagain

Six captures in session 10 agreed. Each frame went out about seven times, so 86% of what the phone sent was a resend. Nine sessions of software changes could not move the rate, because none of them could make this card acknowledge.

Evidence Everything above the radio is written in this repository.

Tested against things we did not write.

A codec can be wrong in a way that round-trips through itself perfectly. So each layer is checked against an independent implementation, and where none exists, against Apple's own devices.

  • LayerWhat is builtChecked against
  • Binary plistBuiltA bplist00 reader and writerChecked againstPython plistlib, which writes our fixtures and reads back what we emit
  • CPIO archiveBuiltA newc writer, and a reader for newc and odcChecked againstbsdtar and libarchive, in both directions
  • DVZipBuiltChunked zlib with stored blocks, and a gzip fallbackChecked againstReal iPhone uploads. No other implementation exists to compare with
  • mDNSBuiltThe DNS wire format and the AirDrop service recordsChecked againstpython-zeroconf, which resolves PTR, SRV, TXT and both address families
  • TLS and HTTPBuiltSelf-signed certificates and a minimal HTTP/1.1 client and serverChecked againstopendrop, as client and as server
  • Discover, Ask, UploadBuiltThe transfer state machine, both halvesChecked againstopendrop both ways, byte-identical, and iPhones for receiving
  • Continuity beaconBuiltA Bluetooth capture tool and a parserChecked againstA real iPhone, not a write-up
  • AWDL linkBuiltNot built here. OWL provides awdl0 on LinuxChecked againstThis is the layer that limits everything above it

Run it Needs the .NET 8 SDK. The desktop app is Windows only. The command line also runs on Linux.

Build it and send something.

git clone https://github.com/UvejsGj/Windfall.git
cd Windfall
dotnet build

dotnet run --project src/Windfall.App              # the desktop app
dotnet run --project src/Windfall.Cli -- receive
dotnet run --project src/Windfall.Cli -- send photo.jpg
dotnet run --project src/Windfall.Cli -- browse    # list nearby peers

To receive from an iPhone, clone the linux branch and follow the hardware runbook. The receiver asks before it saves anything, and that prompt is the only real security boundary in the protocol.
